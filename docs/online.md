# 从「本地原型」到「联网 demo」：怎么回事、怎么做

## 一、为什么现在这个版本是“纯本地”的

你现在打开的页面，其实是三个文件：HTML、CSS、JS。浏览器把它们下载下来，在你的设备上运行。

页面里所有的点评、收藏、图片，都写在 **localStorage** 里——可以理解成“浏览器给你开的一个小抽屉，只在这一台设备的这一个浏览器里”。

所以：
- 换一台电脑 → 抽屉是空的
- 换一个浏览器 → 抽屉是空的
- 发给同学 → 他打开的是同一份页面，但他的抽屉是空的

页面本身**不保存任何东西**，它只是“显示器”。这就是“纯本地”的含义。

## 二、“联网”联的到底是什么

浏览器之间不能互相写数据（安全限制），所以想让 A 写的评论出现在 B 的屏幕上，中间必须有一个**双方都能访问的中转站**——这就是服务器（后端）。

```
你的浏览器  ──写入──▶  后端服务器（一台一直开着的电脑）  ◀──读取──  同学的浏览器
     ▲                        │
     └──────── 数据存在这里 ───┘
```

后端就干三件事：

1. **存**：把点评存进数据库（可以理解成一个永远不关机的 Excel 表格）
2. **发**：给每条点评一个编号，按时间排好，谁来要就给谁
3. **把关**：限制频率、限制长度、过滤脏话、区分房间

补一句：图片如果直接塞进数据库会撑爆，真实产品会放到“对象存储”（专门存文件的柜子）里，数据库只存一个链接。这个 demo 为了简单，图片是压缩后跟着点评一起传的。

## 三、这个项目是怎么改的（只动了一个地方）

原来页面直接读写 localStorage。现在中间加了一层 **Store（存储层）**：

```
界面 (app.js)
    │  只认 Store 的四个方法
    ▼
Store ──┬── 本地适配器：写 localStorage（现在默认）
        └── 联网适配器：写后端 API（配好地址即可）
```

好处：
- 页面代码一行没改，两种模式都能跑
- 断网了自动退回本地，恢复后再补传（有个待发送队列）
- 想换后端（Cloudflare / 腾讯云 / Supabase）只改一个地址

## 四、怎么开启联网（5 分钟）

1. 注册 Cloudflare（免费），安装 wrangler：
   `npm i -g wrangler`
2. 进入 `server/`：`wrangler login`
3. 建一个 KV：`wrangler kv namespace create FDR`，把返回的 id 填进 `wrangler.toml`
4. 部署：`wrangler deploy`，会得到一个 `https://xxx.workers.dev` 地址
5. 打开页面时带上地址：
   `https://ashanqing.github.io/canteen-radar/?api=https://xxx.workers.dev&room=class1`

同一时间打开这个链接的人，写下的点评会出现在同一个池子里。

## 五、怎么验证真的多人了

1. 电脑开一个窗口，手机开一个窗口，都打开上面那个链接
2. 电脑给「红烧肉盖饭」写一条 5 朵花
3. 手机进同一道菜 → 应该看到这条评价，带「实时」标记
4. 手机那条点评的署名，就是手机上设置的昵称（我的 → 改昵称）

## 六、没有后端时的替代方案

在「我的」页有 **导出分享码 / 导入同学的评价**：
- 点导出 → 得到一串码（其实是整个房间的点评）
- 发给同学 → 他粘进导入框 → 他的页面就出现你的点评

这不是真的联网，但足以在两个人之间演示“数据可以流动”，而且完全不需要服务器。

## 七、几个坑

| 坑 | 说明 |
|---|---|
| 跨域 | 后端必须返回 `Access-Control-Allow-Origin`，worker 里已经写好 |
| HTTPS | 页面是 https，后端也必须是 https，否则浏览器直接拦截 |
| 图片太大 | 现在跟着 JSON 传，图片多会很慢；正式做法是传对象存储拿 URL |
| 免费额度 | KV 读写有配额，几百人以内够用；Supabase 免费项目 7 天不活动会休眠 |
| 数据会被清 | 演示房间随便清，别有心理负担；正式产品要做备份 |
| 谁都能写 | demo 没有登录，同一个链接谁都能写。真实产品需要微信号 + 学生认证 |
