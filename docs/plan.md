## 1. 在线调研发现

### 1.1 需求侧：痛点有数据支撑
湖南科技大学 380 份有效问卷（新湖南《青春合伙人·青年数据说④》，2025-12）：
- 近六成学生以食堂为主阵地；外卖 16.58%、校外餐饮 16.05%。
- 分维度打分：价格 3.7/5（最高）、出餐速度 3.64、口味 3.6（偏低）；外卖口味 3.89、选择多样性 3.78。
- 原话：「食堂虽然便宜，但菜式更新慢，一个学期下来几乎没变化，再好吃的菜也容易吃腻」。
- 健康缺口：「想多吃点轻食，但食堂里这类选择很少」。
- 校外店「好吃但等位久，下午有课来不及」→ 时间成本是硬约束。

→ 三条需求主线：**吃腻了 / 不知道吃什么 / 怕踩雷且怕排队**。

### 1.2 供给侧：现有校园产品几乎全是「管理侧」
- 武汉商学院「用餐评价」二维码、大连海事「食事即办」小程序 = 后勤收集意见的单向问卷。
- 满客宝「智慧食堂评价闭环」：五维评分（口味/卫生/窗口服务/结算设备/就餐环境），差评高频词「偏咸 / 排队久 / 地面油污 / 菜品凉」，派单整改闭环；厂商宣称重复投诉降 78%、满意度升 65%（宣传口径）。
- 结论：**管理侧「反馈管道」很卷，学生侧「发现与决策工具」近乎空白**。

### 1.3 可借鉴机制
- 大众点评星级规则（北京商报 2026-09 官方回应）：星级由「评价诚信度/质量/时间/数量」决定；无「好评抵消差评」；刷好评反降级；差评约 3 天延迟。
  → 启发评价权重模型与防刷规则，并作为可信度卖点白盒展示。
- 上新试吃官（浙商大、安徽信息工程学院）：新菜先请师生试吃再上架。
  → 做成「新菜雷达 + 试吃官首评」，解决「吃腻」，也是 B 端合作抓手。

### 1.4 四个关键洞察
1. 点评对象应是**菜**而非店：用户记住「那道锅包肉」。
2. **高频决策疲劳**：一周 20 次决策，首页必须是决策器而非信息流。
3. **时空约束进模型**：下课 10 分钟、300 米、排队 15 人。
4. **差评可信度是命门**：学生怕实名、管理者想公关 → 匿名 + 认证 + 权重 + 差评保护。

## 2. 用户与场景

主要用户：在校本/硕学生（高频、价格敏感、口味多变）。次要：吃货 KOC。

| # | 场景 | 问题 | 对应功能 |
|---|---|---|---|
| 1 | 11:50 下课，12:10 有课 | 20 分钟内吃什么，哪不排队 | 此刻推荐 + 排队 + 距离 |
| 2 | 连吃两周腻了 | 有什么没吃过的 | 新菜雷达 + 没吃过筛选 |
| 3 | 被某道菜坑过 | 这菜到底行不行 | 踩雷预警 + 慎点榜 |
| 4 | 减脂/月底穷/感冒 | 清淡、15 元内 | 口味/预算/热量筛选 |
| 5 | 想吐槽或安利 | 说了没人听 | 写点评 + 有用 + 口味画像 |

## 3. 差异化
1. **菜品粒度**：评分/榜单/预警都落在 SKU。
2. **可解释推荐**：每条给「为什么」（你常点微辣 / 好评 92% / 排队 5 分钟 / 你没吃过）。
3. **可信评价**：认证徽章、单菜重复评价衰减、短评降权、差评不可被好评抵消。

**不做**：支付点餐、私信、真实导航、B 端后台、真实账号体系。

## 4. 功能设计

### Tab1 此刻（P0）
- 时段问候 + 课表语境（「12:10 有课，留你 8 分钟」）
- 筛选 chips：15元内 / 不排队 / 想吃辣 / 清淡 / 没吃过 / 高蛋白
- 推荐 3 张卡：菜名 + 窗口 + 价格 + 好评率 + 排队分钟 + 2 条推荐理由 + 踩雷徽章
- 「再换一批」：权重扰动 + 翻牌动画
- 今日上新横滑（新菜 + 试吃官首评 + 尝鲜指数）
- 踩雷预警条：「近 7 天 12 条差评集中在『太咸』」
- 社交证明：「你宿舍楼 3 人今天吃了这个」

### Tab2 榜单（P0）
好评榜 / 性价比榜 / 新菜榜 / 慎点榜 / 窗口红黑榜；每条带算法解释弹层；本周 vs 本月。

### Tab3 食堂（P0）
4 个食堂卡（拥挤度、步行分钟、招牌菜、今日菜数）→ 窗口 → 菜品；顶部搜索 + 空态。

### Tab4 我的（P1）
我的点评（可删）、收藏/想吃、避雷清单、口味画像 → 「干饭人格」分享卡。

### 写点评（P0）
五维星级（口味/分量/性价比/等待/温度）+ 快捷标签 + emoji 图 + 140 字短评；提交后实时更新均分并持久化；页面明示权重规则。

### 全局（P1）
关于页（产品说明 + 算法说明 + 虚构数据声明）、首次引导。

## 6. 算法设计

- 推荐：`0.22·口味匹配 + 0.20·好评率(Wilson) + 0.15·新鲜度 + 0.15·(1-排队) + 0.12·性价比 + 0.08·距离 + 0.08·(1-风险)`，筛选条件动态改权重，理由由最高权项模板生成。
- 榜单：`Wilson下限 × log(1+评价数) × exp(-Δt/14d)`。
- 踩雷指数：`差评率 × Σ标签权重 / 样本修正`，>0.35 标「慎点」。
- 评价权重：认证 1.0；新号 0.5；同菜重复 0.5ⁿ；<5 字 0.6。
- 种子数据：虚构「南山大学」4 食堂 / 15 窗口 / 60 菜 / ~180 条学生口吻短评。

## 7. 技术方案与部署

- 文件：`index.html` + `assets/{styles.css,app.js,data.js}` + `docs/`，hash 路由，localStorage 持久化。
- 不引外链图片/CDN：CSS 渐变 + Emoji + 内联 SVG。
- 部署：API 建公开仓库 `canteen-radar` → push → 开启 Pages(main/root) → 轮询 build → Node fetch 校验 200 与资源 → 移动视口截图自检。
- 验收：公开免登录 · 首屏 <2s · 全链路可用 · 刷新保留 · 375px 无横滚 · 关于页含算法与虚构声明。

## 9. 风险与备选

| 风险 | 应对 |
